# v2.1 隔离验收

本次修订恢复多列卡片墙与解释全文的完整卡正文。候选分支为
`feature/literature-card-v2.1`；尚未合并 main、替换已安装 skill 或应用到正式 Vault。

## 修改

- 四个原生 Cards 视图统一 `cardSize: 260`。默认显示封面、期刊、年份、verdict
  与最多两行 `card_summary`；其他属性仍可通过原生属性设置打开。
- 完整卡采用十二部分结构：概念和叙事主线展开，步骤可折叠；方法逐项解释；
  证据表集中提供出处；可信度、详细课题判断和来源折叠。分拣卡保持简短。
- 新增 `fill_card_dates.py`：只读 Zotero，补空日期，已有日期不覆盖；缺少 Zotero
  日期时使用原文件创建日期。默认 dry-run，应用时逐文件备份。
- 数字核验忽略反引号中的来源文件路径，继续核验反引号中的科学数值。
- 仅改正文的请求复用缓存全文及封面、GA 记录，跳过封面流程。

四张完整卡使用已有 MinerU 全文缓存，运行 `verify_card_numbers.py` 检查整张卡，
包括保护的历史全文：

|---|---:|---:|
| Chen | 108 | 0 |

保护的历史全文仍原样保留。Harmsen 区分主要终点阴性与次要、探索结果；
Cocuzza 区分扫描状态、内部验证与临床效能；Wang 区分各数据集内评估与外部验证。

## 保留与应用边界

生图零次，MinerU 上传零次；四张封面、缓存全文、GA 记录、课题连接与判断、
阅读记录和升级前全文均保留。正式 Vault 受检文件与已安装 skill 的哈希未改变。
私人档案、卡片、缓存和截图均在 Git 之外，公开候选只包含规范与可复用代码。

确认后才能执行正式应用。应用前完整备份正式 Vault 与已安装 skill，核对备份后
再合并候选、替换 skill、补日期、安装四张正文及 Base/CSS，并重新原生验收。
任一步失败即停止，使用该步前的备份回退。
